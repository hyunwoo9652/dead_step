데드 스텝 (Dead Step) — 실행 안내
================================

1. ZIP 압축을 먼저 풀어 주세요. 압축 안에서 직접 실행하지 마세요.
2. Windows에서 실행.bat를 더블클릭하세요.
3. Python이 없다면 https://www.python.org/downloads/ 에서 Python을 설치하세요.
   설치 시 Python 실행 경로 등록 옵션을 선택하면 편합니다.
   Python의 기본 설치 구성인 Tcl/Tk 및 IDLE을 포함해 주세요.
4. 다시 실행.bat를 더블클릭하세요. 별도 pip 설치는 필요 없습니다.

macOS/Linux: 터미널에서 이 폴더로 이동한 뒤 python3 main.py 실행.
Tkinter가 없거나 그래픽 디스플레이에 연결할 수 없으면 로컬 브라우저 화면으로 전환합니다.
터미널에 표시되는 http://127.0.0.1:... 주소를 브라우저에서 열 수 있습니다.
로컬 서버 생성도 허용되지 않는 환경에서는 콘솔 화면으로 전환합니다.
브라우저 화면을 직접 선택하려면 python3 main.py --web 를 실행하세요.
Linux 배포판에 따라 Tkinter 화면에는 python3-tk 패키지가 따로 필요할 수 있습니다.
브라우저 화면과 콘솔 화면은 Python 표준 라이브러리만으로 실행됩니다.

콘솔 화면에서는 w/a/s/d로 이동하고, scan 행1 열1 행2 열2로 탐색합니다.
행·열 좌표는 0부터 시작합니다. 명령 목록은 화면 아래에 표시됩니다.

조작
----
방향키: 이동 / S: 탐색 시작 및 취소 / Esc: 탐색 취소
탐색 중 두 칸 좌클릭: 정보 확인과 턴 진행
우클릭: 위험 예상 칸 ! 표시 및 해제 (턴 소비 없음)
R: 새 게임 / 같은 맵 다시 도전 버튼: 동일 맵 재시작

흰 숫자: 이동한 칸 주변 8칸의 감염원 수.
파란 s숫자: 선택 칸을 포함한 주변 3×3(9칸)의 감염원 수.
탐색은 현재 플레이어 중심 5×5 범위의 벽이 아닌 서로 다른 두 칸을 선택합니다.
한 칸만 선택했을 때는 턴이 진행되지 않으며, 다시 클릭하면 선택이 해제됩니다.

기본(보통) 규칙
--------------
15×15 맵, 감염원 8개, 상하좌우 한 칸 이동.
감염체는 BFS 최단거리 추격 → 무작위 한 칸 이동을 반복.
매 유효 행동마다 감염체가 한 번 이동. 실시간 추격은 아닙니다.
감염원이나 감염체 접촉 시 패배. 출구 도착 시 즉시 승리.
종료 후 감염원 위치가 공개됩니다.

문서의 미정 사항에 대한 구현 선택
--------------------------------
시작점은 좌측 아래, 출구는 우측 위, 감염체는 좌측 위.
벽 32개(보통), 시작점 중심의 맵 내부 3×3 구역은 감염원·벽이 없습니다.
벽과 감염원을 피하는 탈출 경로가 존재하는 맵만 생성합니다.
단, 경로 존재가 모든 선택을 논리로 확정할 수 있다는 보장은 아닙니다.
감염체는 감염원의 영향을 받지 않고 벽만 피합니다.
BFS 경로가 없거나 랜덤 이동 후보가 없으면 감염체는 제자리에 있습니다.
잘못된 이동·탐색 선택은 턴을 소비하지 않습니다.
탐색 결과를 보고 선택을 되돌릴 수 없도록 두 지점 확정 후 함께 공개합니다.
숫자는 자동으로 영역을 펼치지 않으며 감염원을 직접 공개하지 않습니다.

확장 기능
---------
쉬움: 감염원 5개 / 벽 22개
보통: 감염원 8개 / 벽 32개
어려움: 감염원 10개 / 벽 40개
최고 기록은 각 난이도에서 가장 적은 탈출 턴 수입니다.
Windows: %LOCALAPPDATA%\DeadStep\records.json 에 저장.
저장 권한이 없으면 게임은 계속 작동하며 메시지를 표시합니다.
같은 맵 재도전도 기록에 포함됩니다. 경쟁용 랭킹이 아닌 개인 기록입니다.

소스 안내
---------
board.py: 맵 생성, 요소 배치, 주변 감염원 수.
player.py: 이동·탐색 검증 및 정보 제공.
enemy.py: BFS 추격과 랜덤 이동.
game.py: 게임 상태, 턴 순서, 승패 판정과 기능 연결.
ui.py: Tkinter 화면, 입력, 난이도 선택과 기록 저장.
web_ui.py, web_ui.html: Tkinter가 없는 환경의 로컬 브라우저 화면.
terminal_ui.py: 그래픽 화면과 로컬 서버를 사용할 수 없는 환경의 콘솔 화면.
main.py: 게임 실행 진입점.
settings.py: 공용 상수와 인접 좌표.
test_engine.py: 규칙 검증. python -m unittest -v test_engine.py 로 실행.
test_web_ui.py: 브라우저 화면용 상태 처리·정보 비공개·기록 저장 검증.
전체 자동 테스트: python -m unittest -v test_engine.py test_web_ui.py
핵심 구현은 5개 역할 파일과 공용 진입점·설정 파일로 분리했습니다.
맵 상태는 좌표 집합으로 관리합니다. 과제의 2차원 배열 적용을 위해
별도의 15×15 terrain 배열도 엔진에서 제공합니다.
terrain[r][c]에 벽과 감염원 상태를 저장하고, 좌표 집합은 탐색에 활용합니다.

실행 파일 만들기 (선택 사항)
---------------------------
Windows에서 EXE_만들기.bat 실행. 최초에는 인터넷이 필요합니다.
PyInstaller를 작업 폴더의 가상환경에 설치하고 dist\DeadStep.exe 를 생성합니다.
생성된 EXE는 Python 없이 실행할 수 있습니다. 이 패키지에는 EXE가 포함되지 않습니다.
Windows 패키징 및 실제 Windows 화면 동작은 이 제작 환경에서 검증하지 못했습니다.
이 제작 환경에는 tkinter와 그래픽 디스플레이가 없어 Tkinter 창 자체는 열어 보지 못했습니다.
코어 규칙 자동 검증과 Python 문법 검사를 완료한 소스입니다.

문서 기준: deadstep_개념설계_7개기능수정.docx 및 데드스텝_제안서_WORD(3).docx.
